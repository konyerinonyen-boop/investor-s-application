# Concrete refactor checklist

## 1. `config/services.php`
Add this to the existing `bytid` array:

```php
'webhook_secret' => env('BYTID_WEBHOOK_SECRET'),
```

Add to `.env` (use the signing secret generated by Bytid's webhook endpoint settings):

```dotenv
BYTID_WEBHOOK_SECRET=whsec_replace_with_real_endpoint_signing_secret
```

Do not commit the actual secret.

## 2. Event deduplication table
Create a migration for `bytid_webhook_events` with:

```php
Schema::create('bytid_webhook_events', function (Blueprint $table) {
    $table->id();
    $table->string('event_id')->unique();
    $table->string('event_type', 100);
    $table->timestamp('processed_at')->nullable();
    $table->timestamps();
});
```

The unique `event_id` is essential because providers retry webhooks. In processing code, claim the event ID transactionally and make sure an already processed event is acknowledged without repeating side effects.

## 3. Webhook signature verification
Implement a dedicated `BytidWebhookController`. It must use `$request->getContent()` for the exact raw body, not `$request->all()` or re-encoded JSON. Parse the `Bytid-Signature` header in the format documented by Bytid (`t=...,v1=...`), reject missing/invalid timestamps and timestamps more than 300 seconds old or in the future, and compare the expected HMAC with `hash_equals`.

The expected signature is HMAC-SHA256 using the endpoint signing secret over:

```php
$t . '.' . $request->getContent()
```

Only after signature verification should the controller parse JSON, read `Bytid-Event` and `Bytid-Event-Id`, and call the webhook processing service. Return a 2xx response promptly for successfully accepted/processed events. Return a 4xx response for invalid signatures or malformed requests.

## 4. Route
In `routes/api.php`, register the endpoint outside the `auth:sanctum` and `verified` group, but inside or outside the existing `v1` prefix consistently with the URL configured in Bytid. If registered in the existing `Route::prefix('v1')` group, the endpoint will be `/api/v1/webhooks/bytid`.

Do not apply `kyc_verified` to the webhook; the provider does not authenticate as an investor. The webhook authenticates with its signature instead.

## 5. Document references
In `BytidVerificationService::verifyDocument`, generate a unique reference for every attempt, for example:

```php
$reference = 'kyc-' . $profile->id . '-document-' . bin2hex(random_bytes(8));
```

Store that submitted reference in `identity_verification_reference` **before or atomically with submitting the request** so webhook results can be matched to the exact attempt. Do not replace it with a provider result ID unless you add a separate database column for the provider ID. A fixed reference such as `kyc-{profileId}-document` is unsafe for retries because an old event could be mistaken for the latest attempt.

Check the actual Bytid response shape and ensure its webhook `data.reference` contains this submitted reference. If it does not, persist the provider's returned document ID in a separate column and correlate using the provider's documented webhook field.

## 6. Result mapping
Keep result mapping in a dedicated service, not the controller. Conservative rules:

- Provider `verified` + face match `matched` + document type match `true` + required registry check `verified` => identity status `verified`.
- Provider `rejected` or explicit face match `not_matched` => identity status `rejected`.
- Provider `review`, missing checks, `face_unavailable`, unknown statuses, or incomplete data => identity status `pending` and manual review/retry path.
- Only update overall `kyc_status` to `verified` through the existing final approval workflow once all required KYC checks and approval rules pass.
- `failed`/`expired` liveness should mark that attempt failed and leave the overall KYC application eligible for retry; it should not permanently reject the whole profile.

## 7. Controller responsibilities
`KycController` should keep the user-facing KYC endpoints (`update`, `submit`, `status`) and only thin methods to start liveness or check the user's session. Put provider calls, webhook verification, idempotency, and result mapping in separate services/controllers.

The old `/kyc/bytid/complete` endpoint may remain as a compatibility/status endpoint, but it must not be the only place where results are persisted. The webhook is the durable asynchronous path.

## 8. Storage consistency
`KycService::storeUploadedFiles()` currently saves files to the `public` disk, while `BytidVerificationService::readImage()` prefers `local` and falls back to `public`. This fallback works but KYC images are identity documents; plan to move them to private local storage and stop exposing document URLs publicly. Migrate existing files carefully before removing the fallback.

## Validation commands

```bat
php artisan route:list --path=webhooks
php artisan migrate --pretend
php artisan test
php artisan config:clear
```

Run the migration for real only after reviewing it and confirming the active database.
